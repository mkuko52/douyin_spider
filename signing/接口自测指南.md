## 1. 准备一份「活着的 www 登录态」cookie

现成可用的两份（都是浏览器/sms_login 导出的 storage_state）：

| 文件 | 说明 |
|---|---|
| `comment_reply/js_reverse_cache/private/browser_state.json` | 本轮从浏览器导出的登录态 |
| `sms_login/js_reverse_cache/private/async_session.json` | sms_login 的会话 |

**先确认它还没过期**（关键：抖音同一账号再登录会让旧会话失效）：

```bash
cd signing
python check_data_interfaces.py --cookie-file <上面任一文件>
# 若全报「未登录/会话过期（401）」→ 换一份，或重新登录后重导
```

> 重新获取：浏览器登录 www.douyin.com 后导出 storage_state；或 App/CLI 跑一次 `sms_login`。

常用参数：

| 参数 | 作用 |
|---|---|
| `--skip 评论回复,关键词搜索` | 跳过某些项（中文名或项目名都认） |

| 参数 | 作用 |

## 4. 后端路由（FastAPI，6 个 POST /api/data/*）

```bash
# 1) 起后端（在仓库根；用后端自带 venv）
cd D:/spider_projects/web/douyin_spider
backend\start.bat                     # 首次先 python backend/runtime/bootstrap.py --install
# 或  backend\runtime\venv\Scripts\python.exe -m uvicorn backend.main:app --host 0.0.0.0 --port 8000

# 2) 拿到 App JWT —— 真机走 /api/auth/send_code + /api/auth/sms_login（真短信）
#    没有真短线时，可以手动把一份活会话灌进后端缓存 + 造 token：
python - <<'PY'
import json, sys; sys.path.insert(0, ".")
from backend.core.cache import get_cache
from backend.api.deps import create_token
PHONE = "13800138000"
st = json.load(open("signing/comment_reply/js_reverse_cache/private/browser_state.json", encoding="utf-8"))
jar = {c["name"]: c["value"] for c in st["cookies"] if "douyin" in (c.get("domain") or "")}
get_cache().set_json(f"dy_login:{PHONE}", jar, ttl=1800)
print(create_token("1764073121522141", phone=PHONE))
PY

# 3) 用上面的 token 调 6 个路由
TOKEN=<上一步打印的 JWT>
curl -s -X POST http://127.0.0.1:8000/api/data/detail \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"aweme_id":"7626316866109066511"}'
curl -s -X POST http://127.0.0.1:8000/api/data/comments \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"aweme_id":"7626316866109066511","count":3}'
curl -s -X POST http://127.0.0.1:8000/api/data/replies \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"aweme_id":"7626316866109066511","comment_id":"7626681743785050939","count":3}'
curl -s -X POST http://127.0.0.1:8000/api/data/feed \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{"count":3}'
curl -s -X POST http://127.0.0.1:8000/api/data/user \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"sec_user_id":"MS4wLjABAAAApBXenoFyCKJlEi9DItxR21JPOlhmiGbMiRGugv4aPbZxc6615SAQ7kctt1Lhq_Qa"}'
curl -s -X POST http://127.0.0.1:8000/api/data/search \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"keyword":"minecraft","count":3}'
```

统一响应：`{"success":true,"status_code":0,"message":null,"data":{…}}`。
HTTP 码：`401` = 无 token / token 缺 `phone` / **会话不是 www 登录态**；`400` = 无可用会话或签名项目跑不起来。

## 5. 结果对照 / 已知条件

| 接口 | 需要 | 过了长什么样 |
|---|---|---|
| 视频详情 | 任意带 `ttwid` 的会话 | `status_code=0` + `aweme_detail` |
| 评论列表 | 同上 | `status_code=0` + `comments/total/cursor` |
| **评论回复** | 同上 **+ 真 bdms a_bogus**（`--abogus-source nv8`，或开常驻服务） | `status_code=0` + `comments` |
| 视频列表 | 任意会话 | `status_code=0` + `aweme_list` |
| 用户信息 | 任意会话 | `status_code=0` + `user` |
| **关键词搜索** | **真 www 登录态** | `status_code=0` + `aweme_list`；否则 `2483 请先登录` |

排查顺序（全报 401 时）：
1. cookie 是不是**最近一次**登录的（同账号再登录会让旧会话失效）；
2. 用 `--no-check-login` 看抖音原始响应，区分「会话问题」还是「接口问题」；
3. `评论回复` 空 body → 没走 nv8（确认 `--abogus-source nv8` 或常驻服务在跑）。
