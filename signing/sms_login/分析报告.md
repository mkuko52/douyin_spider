## 2. 请求全貌（浏览器抓包真值）

```
POST /passport/web/sms_login/?<30 个 query 参数>   HTTP/1.1
Host: login.douyin.com
Accept: application/json, text/javascript
Content-Type: application/x-www-form-urlencoded
Origin: https://www.douyin.com
Referer: https://www.douyin.com/
web-sdk-version: 1
sec-ch-ua: "Google Chrome";v="153", "Not_A Brand";v="8", "Chromium";v="153"
x-tt-passport-aid-sign: <HKDF+HMAC>
x-tt-passport-csrf-token: <cookie passport_csrf_token>
x-tt-passport-trace-id: <== biz_trace_id>
x-tt-passport-verify-portrait: <uuid>.login
x-tt-session-dtrait: d0_<b64>_<b64>          ← 浏览器会带；实测**本接口非必需**
Cookie: ttwid / passport_csrf_token / odin_tt / s_v_web_id / …

service=https%3A%2F%2Fwww.douyin.com&mix_mode=1&mobile=<enc>&code=<enc>&fixed_mix_mode=1
```

query 参数（30 个，顺序即线上顺序）：

```
passport_jssdk_version passport_jssdk_type is_from_ttaccountsdk aid language
account_app_language ts is_from_iesaccountsaas p_ui p_ca p_ca_real fp verifyFp
account_sdk_source account_sdk_source_info p_js_v p_js_t p_zt p_ver p_ver_real
request_host p_bd p_ts p_no biz_trace_id device_platform
sign qs msToken a_bogus
```

**参数生成位置（逆向定位）**

| 参数组 | 生成者 | 算法 |
|---|---|---|
| `mobile` / `code` / `qs` / `account_sdk_source_info` | 模块 `86465` 函数 `c` | `enc(s) = hex(utf8(s) XOR 0x05)` |
| `sign` / `qs` | 模块 `86465` 函数 `d` | `sha256(params排序前10 + "&" + body排序全部 + "&app_key=" + APP_KEY)`；`qs = enc(前10个键名)` |
| `APP_KEY` | `client-entry~*.js` | `163e7ce78d58971a41f5b969996d85c2`（aid=6383） |
| `x-tt-passport-aid-sign` | 模块 `370824` | `HMAC(HKDF-Expand(HMAC(ts, appKey)), "aid=…&path=…&ts=…")` |
| `ts` | SDK 常量 | 当天 12:00 UTC 秒级时间戳（整天不变） |
| `a_bogus` | 页面 `bdms`（VM 字节码） | 本项目用 `node/mod.js` 复现；**sms_login 上实测被服务端接受** |
| `p_ts` / `p_no` / `biz_trace_id` | 每次请求生成 | 毫秒时间戳 / 64 位 hex / 32 位 hex |
| `fp` / `verifyFp` | cookie `s_v_web_id` | 设备级 |
| `msToken` | cookie / 响应头 `X-Ms-Token` | 服务端下发 |

## 4. 实现结构（全程异步）

```
sms_login/
├── main.py                      总装（`asyncio.run`）：引导会话 → 组参数 → 发请求 → 打印响应
├── node/
│   ├── abogus_server.mjs        nv8 跑页面同款 **bdms 字节码** → a_bogus（不发网络）
│   ├── dtrait_server.mjs        nv8 跑 uc-secure-dtrait-core → dtrait payload（不发网络）
│   └── mod.js                   pyexecjs2 用的公开移植版（备用，服务端不认）
├── assets/                      bdms / webmssdk / dtrait_core（JSVMP）+ RSA 公钥
├── utils/
│   ├── passport.py              enc / sign / qs / aid-sign / 公共参数 / body（纯 Python）
│   ├── nv8_signer.py            Python → Node(nv8) 桥（a_bogus，异步）
│   ├── dtrait.py                dtrait 拼头：RSA-2048 包 key‖iv + AES-128-CBC
│   ├── dtrait_signer.py         Python → Node(nv8) 桥（dtrait payload，异步）
│   ├── browser_artifacts.py     真实浏览器窄工件（AsyncBrowserArtifacts，备用 a_bogus 来源）
│   ├── signer.py                pyexecjs2 桥（mod.js，备用）
│   └── logger.py                日志
├── tests/test_vectors.py        10 项固定向量验证（离线）
└── js_reverse_cache/            证据（抓包样本 / 逆向笔记 / 探测脚本）
```

### 并发模型

| 层 | 实现 | 并发安全 |
|---|---|---|
| HTTP 出口 | `aiohttp`（`async with session.post(...)`） | ✅ 天生异步 |
| Node 参数服务（bdms / dtrait） | `asyncio.create_subprocess_exec` + `asyncio.Lock` | ✅ 锁内串行 |
| 浏览器窄工件（可选） | `AsyncBrowserArtifacts`（`playwright.async_api`） | ✅ 原生异步 |
| pyexecjs2（`modjs` 备用） | `asyncio.to_thread` | ✅ 同上 |

**分工边界**：Node 只生成参数（`a_bogus`、`dtrait` payload），**不发任何网络**；
Python 独占最终 HTTP 出口（`aiohttp`），并负责 `sign`/`qs`/`aid-sign`/`enc`/RSA+AES 组包。

## 6. 过程中修掉的真实缺陷

1. **`request_host` 多了一个尾斜杠** —— `quote("https://www.douyin.com/")` 得到
   `…douyin.com%2F`，与抓包的 `https%3A%2F%2Fwww.douyin.com` 不一致，
   会让 `sign` 整串错位。必须**不带尾斜杠**。
2. **`ttwid` 被 `requests` 丢掉** —— `ttwid` 由 `ttwid.bytedance.com` 下发，
   cookie 作用域是那个主机；直接 POST `login.douyin.com` 时浏览器之外的客户端
   **不会带上它**，服务端给 `2156`。修法：引导后把会话 cookie 显式重挂到
   `.douyin.com` / `login.douyin.com`（`main.py::bootstrap`）。
   另外 `ttwid` 注册接口的 `aid` 必须是**整数**，传字符串会返回
   `{"status_code":1001,"message":"parse params fail"}`。
3. **`msToken` 缺失** —— 浏览器里它是页面 webmssdk 现场换取的（bdms 会自补进 URL）。
   纯 Python 直连 `mssdk.bytedance.com` 拿不到（`resultCode:-2`），但**任何
   `/passport/web/*` 响应都会在 `X-Ms-Token` 里下发一个**。所以登录前先打一次
   `get_qrcode` 热身（实测 `error_code: 0`）把 token 摘下：`main.py::warm_ms_token`。
4. **`x-tt-session-dtrait` 缺失** —— 浏览器每个 `/passport/web/*` 请求都带。
   payload 要靠 `uc-secure-dtrait-core`（JSVMP）+ 浏览器环境采集，裸 Node 跑不了；
   默认向同站 `send_code` 工件服务（nv8）要 payload，再在 Python 侧做
   RSA-2048 + AES-128-CBC 拼头（`utils/dtrait.py`），段长 `2/344/896`。
5. **参数顺序错位** —— `a_bogus` 签的是**字面 query 串**，所以顺序必须与浏览器一致：
   `… device_platform, sign, qs, msToken, a_bogus`。
6. **`CookieConflictError`** —— `session.cookies.get(name)` 在同一名字跨域
   （`.douyin.com` 与 `login.douyin.com`）时会抛异常；改用 `_jar_get()` 安全取。

对齐后，我们发出的 query 与浏览器**参数个数、名字、顺序完全一致（30 个）**：

```
passport_jssdk_version passport_jssdk_type is_from_ttaccountsdk aid language
account_app_language ts is_from_iesaccountsaas p_ui p_ca p_ca_real fp verifyFp
account_sdk_source account_sdk_source_info p_js_v p_js_t p_zt p_ver p_ver_real
request_host p_bd p_ts p_no biz_trace_id device_platform sign qs msToken a_bogus
```

## 6.6 `7` 的真正含义（2026-09-18 23:17 修正）

把全部尝试按「验证码是否有效」重排，相关性 **100%**：

| 码状态 | 结果 | 样本数 |
|---|---|---|
| **有效码**（刚收到、未被提交过） | **`7 访问太频繁`** | 6/6 |
| **无效 / 已用码** | `1203 验证码错误或过期` | 6/6 |

即：

- `1203` = 验证码在**早期校验**就被拒（压根走不到风控判定）；
- `7` = **验证码有效，但登录请求被风控挡下** —— 它不是频控，而是这个端点上的“被拒”信号。

这正好解释了 `send_code` 的结论：同一套参数、同一个有效码，**只换 a_bogus**，
`send_code` 那边就从成功变成被拒（他们那里是 `2156`）；在 `sms_login` 上的表现就是 `7`。

> 也因此，之前用「无效码」做的 `abogus_ab` 对照是**无效实验**（两组都停在 `1203`），
> a_bogus 从未被真正验证过 —— 它是活的嫌疑人。

## 6.7 分工定型（对齐 send_code 的已验证形态）

| 工件 | 来源 |
|---|---|
| `a_bogus` | **真实浏览器 bdms 现场签名**（`utils/browser_artifacts.py`，`--abogus-source browser`） |
| `x-tt-session-dtrait` | **nv8 补环境**采集 payload + Python RSA/AES（`node/dtrait_server.mjs`） |
| `msToken` | 热身 `get_qrcode` 的响应头 `X-Ms-Token` |
| `sign` / `qs` / `aid-sign` / `enc` / body | 纯 Python（与抓包逐位一致） |
| HTTP 出口 | Python（`requests`） |

浏览器只做**窄工件生成器**（XHR 在 `send` 处拦下，不发业务请求）。
实测**无法**从这条路拿到 `dtrait`/`portrait`/`csrf` —— 那些是 passport SDK 请求构造器加的，
我们自己构造 XHR 就绕过去了；所以 dtrait 必须走 nv8，与 `send_code` 的分工一致。

### 早期错误结论（已推翻）

| 早期说法 | 实测 |
|---|---|
| “号码被打热了，浏览器也一样登不上” | ❌ 浏览器 23:11:34 **登录成功** |

### 响应错误码

| `error_code` | 含义 | 处理 |
|---|---|---|
| `0` + `message: success` | 登录成功，会话 cookie（`sessionid` 等）已下发 | 完成 |
| `1203` | 验证码错误 / 过期 → **参数层已通过**（与浏览器一致） | 换新验证码 |
| `7` | **访问太频繁**：请求已被受理（不是签名/风控拒绝） | 等几分钟 + 复用同一会话 |
| `2156` | 系统繁忙 / 风控拦截（会话不全或调用过密） | 换会话 / 等一会儿 |

`7` 与 `2156` 都是**频控**，不是参数错误：实测同一个生成器在正常节奏下稳定拿到 `1203`
（= 与浏览器一致）。每次 `python main.py` 都会新注册一个 ttwid（新设备身份），
对同一号码反复用新身份登录会很快触发频控；用
`--cookie-file/--save-cookies` 复用同一会话可明显降低风险。

### 与 send_code 项目的对接

验证码靠另一个项目 `../send_code` 发送。两个项目在**真实场景里是分开的**，
所以 `tests/e2e_login.py` 只用 `subprocess` 调它、不 import 任何模块：

```bash
python tests/e2e_login.py --mobile 138xxxxxxxx                     # 发码 → 输码 → 登录
python tests/e2e_login.py --mobile 138xxxxxxxx --skip-send         # 已收到码，直接登录
python tests/e2e_login.py --mobile 138xxxxxxxx --code 123456 --skip-send --dry-run  # 只验接线
```

删除该文件不影响两个项目各自独立运行（唯一的耦合点就是一行命令行调用）。

## 8. 边界与合规

- Node 只生成参数、不发网络；**Python 独占 HTTP 出口**。
- 默认号码/验证码是占位值；交互输入时请填你自己的号码。
- 该接口是**登录**动作：连续失败会累积风控（实测出现 `error_code 7 访问太频繁`
  与 `2156`），不要在短时间内反复调用。
- 只用于授权范围内的接口分析与自有账号验证。
